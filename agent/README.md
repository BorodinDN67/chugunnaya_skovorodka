# 3D LiDAR Mapping & Localization — ROS 2

Решение для финала хакатона «Сервисная робототехника». Цель — построение трёхмерной карты помещения и локализация квадропедального робота на ней в реальном времени по записанным данным.

**Статус:** вычислительное ядро объединяет одометрию, предобработку XYZ, GICP и карту в режимах mapping и localization. В ROS 2 Humble пакет собран, пройдены 21 модульный и один сквозной синтетический тест. Две реальные записи исследованы офлайн. Результаты — в [DATA_ANALYSIS.md](DATA_ANALYSIS.md). Актуальное состояние — в [PROGRESS.md](PROGRESS.md).

## Архитектура

- `lidar_core` — библиотека C++17 с Eigen и PCL внутри пакета `lidar_mapping`. Поза `T_A_B` переводит координаты из системы B в A. Предсказание вычисляется как `T_map_base_prev * (O_prev.inverse() * O_curr)`, где `O = T_odom_base`.
- Буфер принимает позы с целочисленными временными метками в наносекундах на общей шкале времени. Для промежуточной метки он линейно интерполирует позицию и применяет SLERP по кратчайшей дуге для ориентации. Ёмкость и максимально допустимый интервал между соседними отсчётами задаёт вызывающий код. За пределами диапазона и при слишком большом интервале буфер возвращает пустой результат.
- `src/ros_integration/` в пакете содержит ROS 2 адаптер для четырёх режимов. Пакет находится в `ros2_ws` командного репозитория. Команды сборки и тестов приведены в [README пакета](../ros2_ws/src/lidar_mapping/README.md) и в [PROGRESS.md](PROGRESS.md).

## Данные
Источник организаторов: https://github.com/ivr0ma/hackathon/tree/main/hackathon

- bag_for_mapping — построение карты.
- bag_for_localization — локализация в том же помещении по другому маршруту, с динамическими объектами и резкими движениями.
- Основные топики: /utlidar/cloud_base (14 Гц), /utlidar/robot_odom (100 Гц).
- Контрольный топик: /utlidar/cloud_deskewed.

## Метод
1. Предобработка облака PCL.
2. Интерполяция одометрии и предсказание позы SE(3).
3. Выделение локального участка карты.
4. GICP scan-to-map с начальным приближением от одометрии.
5. Проверка качества; при отказе — резервная оценка по одометрии.
6. Mapping обновляет карту, localization использует неизменную карту.

## Зависимости
ROS 2, PCL, pcl_ros/pcl_conversions, Eigen, TF2, rosbag2, RViz2, colcon, ament_cmake; Python для анализа. В проверенном образе установлены PCL 1.12.1, Eigen 3.4.0 и ament_cmake 1.3.15.

## Проверка окружения
Примеры команд (пути заменить фактическими):

```bash
ros2 doctor --report
ros2 pkg list | grep -E 'pcl|rviz2|tf2'
ros2 bag info /path/to/bag_for_mapping
ros2 bag info /path/to/bag_for_localization
```

Перед запуском выполнить source /opt/ros/<дистрибутив>/setup.bash для установленной версии ROS 2.

## Сборка и запуск

Собирать пакет через `colcon` из `/ros2_ws` внутри контейнера организаторов `r_hacatonius`. Пакет предоставляет вычислительную библиотеку, синтетические тесты и узел ROS 2. Команды запуска и параметры приведены в [документации адаптера](../ros2_ws/src/lidar_mapping/src/ros_integration/README.md).

## Ожидаемые артефакты
- maps/map_baseline.pcd — контрольное накопление глобальных облаков.
- maps/map_odometry.pcd — карта по кинематической одометрии.
- maps/map_gicp.pcd — основная карта.
- results/ — выходные bag, CSV траекторий и метрик, графики, конфигурации.
- RViz2 — карта, текущий скан, исходная и скорректированная траектории, вид сверху и от третьего лица.

## Оценка
Сравнить три варианта картографирования; оценить устойчивость локализации, невязку, долю успешных регистраций, время обработки (mean, median, P95, P99, max), пропущенные сканы и throughput. Целевой интервал лидара — около 71.4 мс. При отсутствии эталонной траектории не заявлять абсолютную точность на основе внутренних метрик.
