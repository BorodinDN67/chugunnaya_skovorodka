# AGENTS.md — инструкции Codex

## Цель
Разработать решение финала хакатона «Сервисная робототехника»: построить 3D-карту по bag_for_mapping и локализовать квадропедального робота на ней по bag_for_localization в реальном времени. Физический робот недоступен. Сначала рабочий end-to-end baseline, затем улучшения.

Источник: https://github.com/ivr0ma/hackathon/tree/main/hackathon

## Инфраструктура организаторов

- Базовое окружение — оригинальный Docker-стенд Unitree Go2 с ROS 2 Humble в корне командного репозитория `chugunnaya_skovorodka`. Compose монтирует `ros2_ws` в контейнер как `/ros2_ws`. Вся разработка ведётся в этом репозитории. Соседний checkout `hackathon` служит резервной копией.
- Пакет `lidar_mapping` размещать в существующем `ros2_ws/src/lidar_mapping/` стенда. Собирать через `ament_cmake` и `colcon`. Исходники и заголовки ядра размещать в `src/core/` и `include/lidar_mapping/core/`. Ядро использует C++17, Eigen и PCL. Компоненты ROS 2 размещать в `src/ros_integration/`.
- Сохранять оригинальные `Dockerfile`, `docker-compose.yml`, `play_viz.sh`, `go2.rviz` и `README.md` стенда. Инструкции по сборке решения вести в README пакета.

## Данные
- `/utlidar/cloud_base` — облако в координатах робота, 14 Гц.
- `/utlidar/cloud_deskewed` — компенсированное облако в глобальных координатах точки запуска; не трансформировать повторно.
- `/utlidar/cloud` — сырое облако лидара.
- `/utlidar/robot_odom` — кинематическая одометрия, 100 Гц.
- `/utlidar/robot_pose` — предоставленная оценка позы, не ground truth.
- `/utlidar/imu`, `/lowstate` — дополнительные данные. IMU 100 Гц, калибровка относительно base_link отсутствует по брифу.
- Камера 15–30 Гц по брифу, возможны пропуски; наличие топика проверить.

Проверить фактические типы, поля, frame_id, timestamps, QoS, TF, формат хранения и длительность bag. Во второй записи динамические объекты, резкие повороты и ускорения. Облака разреженные. Начальные системы координат двух записей могут отличаться.

## Baseline
Odometry-assisted GICP Scan-to-Map, 6DoF. ROS 2, C++17 при совместимости, PCL, pcl_ros/pcl_conversions, Eigen, TF2, rosbag2, RViz2, ament_cmake/colcon; Python для метрик. Использовать готовый PCL GICP, не писать ICP/GICP с нуля. Не включать Nav2, SLAM Toolbox, камеру, отдельную IMU fusion, нейросети или графовую оптимизацию до рабочего baseline.

## Этапы и критерии приёмки
1. Проверить окружение и входные данные; показать выводы команд.
2. Контрольная карта: накопить cloud_deskewed, удалить некорректные точки, проредить, сохранить map_baseline.pcd, показать в RViz.
3. Карта по одометрии: cloud_base + интерполированная robot_odom; сохранить map_odometry.pcd и траекторию.
4. Изолированный эксперимент GICP: несколько пар реальных сканов и локальных под-карт на прямых и поворотах; показать до/после, матрицы, невязку, overlap, время и коррекцию относительно odom.
5. Mapping: GICP scan-to-map, проверка качества, ключевые кадры, сохранить map_gicp.pcd. Сравнить с контрольными картами.
6. Localization: загрузить карту, определить начальную позу, использовать то же ядро регистрации, не изменять карту. Проверить вторую запись.
7. Метрики, сравнения, профилирование, оптимизация.
8. Запись выходного bag, RViz, документация и материалы защиты.

Не переходить к следующему этапу без проверки предыдущего, кроме согласованного обхода. Если GICP mapping ухудшает карту, использовать лучшую проверенную контрольную карту для отладки localization, обозначив происхождение.

## Вычислительное ядро
- Удалять NaN/Inf, фильтровать диапазон, при необходимости корпус робота, умеренно прореживать. Не удалять пол и стены без обоснования.
- Буфер одометрии: интерполяция позиции и SLERP ориентации на timestamp скана. Не использовать несинхронизированную последнюю позу. Ограничить ожидание и учитывать пропуски. При rosbag play --clock использовать use_sim_time.
- O_k = T_odom_base(k), T_k = T_map_base(k).
- delta_O = inverse(O_prev) * O_k; T_pred = T_prev * delta_O.
- Первый скан инициализирует карту; GICP к пустой карте не запускать.
- Source: текущий скан в base_link. Target: локальная карта в map. Initial guess: T_pred. PCL gicp.align(output, T_pred); getFinalTransformation() возвращает полное T_map_base, не умножать повторно на guess.
- Проверять сходимость, конечность и корректность SE(3), невязку, число/долю соответствий, величину коррекции, достаточность точек и по возможности вырожденность геометрии. hasConverged() недостаточно.
- Успех: T_k = T_candidate. Неудача: T_k = T_pred, не добавлять скан в карту, публиковать диагностику. При последовательных неудачах обозначать потерю локализации.
- Mapping: преобразовать принятый ключевой скан в map и добавить к карте с периодическим voxel downsampling.
- Localization: карта неизменна; начальная поза параметрами/RViz допустима с документированием. Не считать начальные позы двух bag совпадающими. При необходимости глобальная регистрация FPFH/RANSAC или перебор гипотез; локальный GICP не гарантирует глобальный поиск.
- TF: map -> odom -> base_link; T_map_odom = T_map_base * inverse(T_odom_base). Не публиковать конфликтующие TF и выдуманные extrinsics.

## Стартовые параметры (гипотезы)
| Параметр | Значение |
|---|---|
| scan/map voxel | 0.05 м |
| min/max range | 0.3/30 м |
| local map radius | 10 м |
| GICP max correspondence | 0.5 м |
| GICP iterations | 30 |
| transformation epsilon | 1e-4 |
| keyframe translation/rotation | 0.2 м / 10° |

Выносить параметры в YAML. Подбирать пороги на данных mapping. Для разреженных облаков проверить достаточность соседей GICP. Deskewing рассмотреть после проверки временных полей и координат.

## Метрики и выходы
Публиковать карту, локальную карту, aligned cloud, pose/odom, path и diagnostics; показывать исходную и исправленную траектории. Предлагаемые топики: /mapping/map, /mapping/local_map, /mapping/aligned_cloud, /localization/pose, /localization/odom, /localization/path, /localization/diagnostics, /localization/processing_time. Адаптировать к существующему коду.

Измерять steady_clock: preprocessing, sync, crop, registration, validation, map update, full pipeline. Сохранять CSV, mean/median/P95/P99/max, throughput, пропуски, latency/очередь, долю успешных регистраций. Цель 14 Гц (~71.4 мс между сканами); проверять воспроизведение 1x без растущей очереди. Без подтверждённого ground truth не выдавать невязку/сравнение с odom за абсолютную точность. ATE/RPE только при наличии подходящего эталона. Сравнивать карты одинаковым способом, анализировать повороты и динамические участки.

## Правила разработки
Изучи существующий репозиторий и PROGRESS.md. Не переписывай рабочие компоненты без необходимости. Общие модули preprocessing, odometry_buffer, registration, map_manager, metrics; отдельные режимы mapping/localization или один конфигурируемый узел. Сохранять исходные bag неизменными. Не коммитить большие данные и артефакты сборки. Не выполнять разрушительные Git-команды без согласования.

После каждой задачи: собрать, протестировать, показать команды и реальные результаты, перечислить изменённые файлы, ограничения, обновить PROGRESS.md и README. Различать написано/собрано/запущено/проверено. Не выдумывать измерения. Фиксировать рабочие версии. При блокере сообщить точную ошибку и предложить минимальный обход.
